# Sony AF：从热图和候选分数到检出判定

范围：A7 IV 6.02、A7R V 4.00、A1 II 4.00 的本地发布件。地址为 CP 文件偏移，除非另标 VA；回放用固定 SHA-256 的原 Thumb 镜像，基址 `0x108000`。未使用机身或真实 NPU 回调。

**结论：一条局部分支可以是单阈值，但机内不存在一个已证实、通用的 `max(heatmap) > T` 来决定 AF 检出。** 至少要分别观察四种结果：热图峰是否存在、单帧候选或部位是否有效、XED/XHD 验证状态、是否被上层采用为 AF 目标。这些结果可以不同。

| 阶段 | 判定机制 | 证据与边界 |
|---|---|---|
| A7 IV FDN/PDN 结果接收 | FDN 按方向选门限，有符号 `FaceScore > T`；PDN 两眼各自做有符号 `score > T`。相等为假。 | 原指令回放。发布默认原始整数：FDN 两方向均 `-287995`，PDN `590558003`。这是结果记录的有效位，不是任意热图的阈值或 AF 是否锁定。[证据](A7IV-WBI2-DETECTOR-EVIDENCE.md) |
| A7R V/A1 II 人体 Pose 热图 | JNP 参数有峰次序、峰门限选择、分组、向量/代价、最大姿态数，不像单点取全局最大值。 | 由参数字段和日志定位，尚未回放峰提取与分组执行器；没有从原始人体热图恢复最终接受公式。[张量边界](COCO-KEYPOINTS-ASSESSMENT.md) |
| A7R V/A1 II XED 局部部位 | 作业参数分别给出左眼、右眼、鼻的 `heat_th` 与峰选择参数。A7R V CP 消费器分别读三路峰计数，计数零跳过该路；非零循环读取位置与定点峰分数。 | A7R V `+0x1b7f34..+0x1b8006` 原指令；A1 II 对应 `peak_num eyeL/eyeR/nose` 引用 `+0x1ef29c/+0x1ef2a4`。三路计数是 JNP 输出，不是最终主体有效位。没有恢复热图零点、原厂峰定义和比较边界；尚未把 COCO 动物槽 18 的所有输出与此作业一一绑定。 |
| A7R V/A1 II XHD 候选 | 解码作业收到每类/部位 `thr/thr_per`、全局 `thr_glbl`、前景/背景 `bgfg_thr` 等。CP 再按搜索区尺度对过小的结果框清分。 | 参数打包及短边清分已回放；未复原 NMS 作业如何使用各门限、原始 logits 的变换或比较顺序。清分不会删除该记录。[NMS 接口](CP-XHD-NMS.md)、[结果转换](CP-XHD-RESULT.md) |
| A7R V/A1 II CP 后处理置信度 | `FaceConfidenceMid/High`、`XhdConfidenceMid/High` 均能读发布配置；按目标、灵敏度及 XHD 类型/部位索引取值。 | 本轮两机回放。门限的存在不证明 High 是获得、Mid 是保持，也不证明它们直接比热图峰或宿主 softmax。 |
| A7R V XHD 空间一致性 | 一条 `judgmentFrameAndXHD` 下游路径把两框的覆盖比例与另一门限比较，低于门限时清掉结果标志。另有与竞争结果比较的路径。 | 本轮原指令回放。距离/空间一致性不能用置信度高低替代；未据此推广到所有主体、运行模式或整个 XHD 管道。 |
| A7R V 跨结果验证 | `calculation_result_status.cpp` 的验证例程读 XHD、Staple、verify 枚举与已有计数，更新计数并返回状态枚举。 | 本轮用连续调用回放；原生枚举全义、调用节拍及最终映射待查，不能写成“实机连续六帧就宣布检出”。 |

## 发布配置：确实不是一个常数

使用原 CP BK4 读取器把第二段记录 `0x60011..0x60015` 拷入已验证的五个 `TuningParamIP` 目的地。后处理 getter 的五个基址分别精确等于对应目的地 `+0x1d0`，并且读取字段均在该 `0x600` 字节记录内。测试把原读取器实际拷出的子视图无修改映射到置信度回放的同一地址，再执行原四个 getter。不是把预期阈值注入 getter。地区成员为两机各自 `ALLLANG`；不能排除运行时覆盖。

| 原始索引，非菜单名 | A7R V Mid / High | A1 II Mid / High |
|---|---:|---:|
| Face：target `0`，sensitivity `3` | `0.8906 / 0.8906` | `0.8906 / 0.8906` |
| XHD：target `3`，type `0`，part `1`，sensitivity `3` | `0.5000 / 0.9540` | `0.5000 / 0.8148` |
| XHD：target `3`，type `3`，part `1`，sensitivity `3` | `0.5000 / 0.9270` | `0.5000 / 0.6040` |
| XHD：target `6`，type `3`，part `1`，sensitivity `3` | `0.5000 / 0.8779` | `0.5000 / 0.6088` |

两机 Face target `0` 在 sensitivity 原始索引 `1..5` 的 Mid、High 都依次为 `1.0000, 0.9609, 0.8906, 0.5390, 0.1640`。这也反证了「Mid/High 永远是两个不同阈值，所以必然是滞回」这种推断。表中的 `0.5` 是 getter 对发布配置的实际返回，不是解释宿主阈值的理由；回退值、字段解析与虚表见 [CP 置信度笔记](CP-CONFIDENCE.md)。

## 两个原厂指令反例

**空间门控。** A7R V `judgmentFrameAndXHD` 的条件调用位于 `+0x1c3fa2`，进入 `+0x6ece30`，后者调用 `+0x1c2cdc`。这不是读候选置信度，也不是通常的 IoU，而是以下覆盖系数（正常非退化矩形）：

```text
overlap = area(intersection(A, B)) / min(area(A), area(B))
if overlap < overlap_threshold:
    clear result flag at object + 0x755 + category_index
```

回放使用真实虚表 `+0x138` 与 getter `+0x1c066c`。它沿镜像中的指针 `VA 0x010fd294 → 0x0172424c` 读 `u16[+0x11e]`，即 `0x60011` 发布记录的 `+0x2ee`。有效范围 `1..10000` 除以 `10000`，否则回退 `0.9`；原 BK4 读取器装入发布数据后，getter 实际返回 `0.3`。用真实 getter 和发布门限值确认重叠 `0.30` 保留、`0.25` 清标志。另用 `0.5` 夹具确认：候选分数 `0.99`、重叠 `0.50` 保留，重叠 `0.45` 清标志；重叠 `0.55` 时把分数降到 `0.01` 仍保留。两框完全嵌套但面积比 `1:25` 时返回 `1.0`，不是 IoU 的 `0.04`。保留只意味着**没被这道门剔除**，不是当场新建检测。未回放竞争分支或证明机身不会覆盖参数。这更正了 `debug/deepseek_xhd/NATIVE-PARAMETER-CONSUMER.md` 把 `+0x1c2cdc` 当作取候选分数的旧注释。

**历史计数。** 在 A7R V `+0x6f5892`，固定输入枚举 `(xhd=1, stpl=0, verify=0)`，保留对象 RAM 连续调用：诊断名为 `M` 的字节从 `1` 增至 `5`，第 1 至 5 次返回枚举 `1`，第 6 和 7 次返回枚举 `2`。`xhd` 改为 `0` 后，该字节和返回都为 `0`。实验只拦日志；状态字段、分支和返回由原指令更新。另有 `XedResultInvalidater` 路径 `+0x1cdc80` 根据内部类型读不同计数字节并与通过虚表取得的阈值比较。它们说明 CP 并非把分数阈值化就结束，但不能把状态枚举直接翻译为屏幕识别框。

## 对宿主 COCO 解码的含义

动物槽 18 目前的「热图有峰 → 把峰合并为一框 → 最大峰当置信度」不应继续当作原厂检出规则。现阶段最有辨识力的中间记录是：**每路峰的数量、位置和原始分数；能否形成有效部位组合；对应 XHD 框、覆盖比例及后处理状态。** 先在正图、难负图和空景上统计三关各自的通过率，再固定真实分数尺度做上层门限实验。不要把 `0.9540` 之类的 CP 数字直接贴到槽 18 最大热图值或鸟/飞机的实验 softmax 上。

目前最大的缺口仍是热图/分类张量到原厂候选的作业内部实现，以及 CP Mid/High 的消费点到最终 `valid` 或 AF 接管状态的完整调用链。下一步优先绑 XED 三路峰和 XHD 结果的作业输入，再从 `XedResultInvalidater`、验证状态及输出 `valid` 反向固定消费者；不靠再扫一个全局分数阈值来填这段缺口。
