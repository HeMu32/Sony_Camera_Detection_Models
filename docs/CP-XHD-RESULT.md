# A7R V / A1 II：原始 XHD 结果转换

`parsers/xhd_cp_result.py` 处理的是 **CP 已收到的 XHD 候选框缓冲区**，
不是 NBG 的分类张量，也不是最终的屏幕画框列表。两机的原始转换函数
分别从 A7R V 文件 `+0x1b8eb4` 和 A1 II 文件 `+0x1f01b8` 开始。
原指令回放在遍历结束、进入诊断代码前停下。

| 索引 | 类型与含义 |
|---|---|
| 缓冲区 `+0x520` | `u32` 候选记录数，`0..50`；`51` 进入错误路径 |
| 缓冲区 `+0x524 + 12*i` | 每条 12 字节：`i16 x0,y0,x1,y1`、`u8 type`、`u8 part`、`u16` 置信度 |
| CP 输出 `+0x04 + 16*i` | `float32` 分数、四个 `u16` 矩形边、`type` 和 `part`，再留两字节 |

每个输入记录的两组坐标是**矩形的两个角**，不应画成两个检测点。
坐标以有符号 Q14 解释；原指令以 `(坐标 × 搜索区尺寸 + 512) >> 14`
做轴向缩放，再相对窗口中心旋转，平移到整帧坐标。对两个角排序，
把 `xyxy` 裁到 `[0,帧宽]×[0,帧高]`。转换保留原记录顺序，类型码
大于 `8` 时归到 `8`，`part` 原样保留。原固件日志确认该字段名，
尚未完整验证它的枚举含义。见 [CP XHD/NMS 命令接口](CP-XHD-NMS.md)。

置信度解码是 `raw / 32768`；输入 `0x4000` 得 `0.5`，
`0x8000` 得 `1.0`。转换本身不钳制分数到 `1.0`。当剪裁后的
**短边**小于 `floor(搜索区宽 × 参数字节 / 320)` 时，原程序只把
分数清零，仍保留矩形和记录。参数字节从当前 `TuningParamIP` 配置
的 `+0x187` 读出；这里验证的是公式，不是检测时的实际值。

在 48 个原指令对照中验证了多条记录、0/50 条边界、四种正交旋转、
裁剪、类型回退和小框清分；另外两机均对 `51` 条进入拒绝分支。
最初这些测试只给 CP 注入合成记录。槽 8、10 现已由
[Adam 原 ARM 解码](ADAM-XHD.md) 从真实张量生成该格式；
分别启动两图再合并结果仍不是跨类型 Auto 调度证据。
